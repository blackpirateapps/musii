# Google Drive sync audit

Audited `75325cc` on 2026-11-25. The audit covered folder selection, recursive discovery, interruption and recovery, metadata reuse, progress, sidecars, artwork, and offline cache reconciliation.

## Remediation

The repository regression suite exercises the corrected paths with scripted Drive HTTP responses, SQLite fault injection, and temporary files. The remediation passed all 310 Flutter tests, including 25 sync regression scenarios and a new v10 migration test. Static analysis reported no issues. The symptoms below describe the audited commit.

| Audit findings | Change |
| --- | --- |
| 1–3, 6–8 | Fetch all pages and require complete listings. Commit each folder’s files and traversal checkpoint atomically. Resume at the first unfinished folder. |
| 4, 15 | Key cache entries by Drive version, refresh pinned media from the sync download, and remove unreferenced files. An in-flight cache download checks the version again before publication. |
| 5 | Keep failed items resumable and only advance the last-sync timestamp on success. |
| 9 | Persist force mode and preserve the original result of every checkpointed item. |
| 10 | Abort in-flight Drive requests and roll back reconciliation when cancellation arrives before commit. |
| 11 | Fingerprint sidecars independently, reconcile sidecar removals, and retry transient lyric errors. |
| 12–13 | Restore persisted folder parents on resume and use separate artwork identities for embedded and Drive cover images. |
| 14 | Stage audio under the Drive ID and a sanitized extension. |
| 16–18 | Count unique audio items, clear errors on retry, and subscribe to progress updates before publishing the first snapshot. |
| Account transitions | Scope saved roots, runs, and removals by the live Google account. Cancel active sync on account changes. |
| Partial reconciliation and relationships | Remove tracks and their associated local rows transactionally, then clean disk files. |
| Large collections and slow sidecars | Use ID maps and sets during discovery, chunk unchanged-row updates, and fetch sidecars before the track transaction. |
| Shared drives and shortcuts | List shared-drive roots, include shared items in Drive requests, follow accessible shortcut targets, and avoid folder cycles. |

Regression coverage lives in [Google Drive sync regression tests](../test/integration/google_drive_sync_regression_test.dart), [sync recovery integration tests](../test/integration/library_sync_optimization_and_recovery_test.dart), and [schema migration tests](../test/integration/database_migration_test.dart). Live Android OAuth and live Google Drive behavior still need device validation. ## Reproduced findings

### High impact

1. **Resume can remove tracks that still exist on Drive.** Index tracks A and B. Start a fresh sync with A on page one and B on page two. Stop while page one is in flight, let it return, then resume. The stopped run saved an empty folder queue and marked the root visited. Resume made zero additional list requests, reported one removal, and deleted B from the local library. The scanner marks the current folder visited before it reads any pages, and the checkpoint carries no page cursor. [Drive traversal](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L128) · [Stop checkpoint](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L969) · [Deletion reconciliation](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1361)

2. **An incomplete Drive result can trigger the same local removals.** After indexing A and B, a simulated successful response returned A with `incompleteSearch: true`. The run completed and removed B locally. The request field mask omits `incompleteSearch`, and the scanner accepts the listing as authoritative. Google documents that this flag indicates possible missing results. The fixture verifies the app’s behavior if that condition occurs. [Scan field mask](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L150) · [Google Drive files.list reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list)

3. **SQLite discovery writes can fail while the run records discovery as complete.** A SQLite trigger rejected inserts into `discovered_files`. The callback error escaped to the Dart zone, sync indexed the track from its in-memory listing, and the completed run had `discoveryCompleted = true` with zero discovery rows. The asynchronous callback is passed to a synchronous callback slot and its future is discarded. A crash after this marker but before reconciliation could leave resume trusting an incomplete snapshot. [Callback invocation](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L202) · [Discovery write and completion marker](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L947)

4. **An updated track can keep playing the old cached audio.** Cache and pin a track, then change its Drive checksum and media bytes. Sync persisted the new checksum and kept the pin, but `getOrDownloadTrack` still returned the old bytes. The cache hit checks the track ID, cache state, and file existence, and metadata refresh leaves the audio cache entry intact. [Track metadata upsert](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1755) · [Cache hit](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/cache/data/repositories/cache_repository_impl.dart#L49)

5. **Every audio download can fail while the run reports success.** Return HTTP 429 for both media downloads on a new library. The run recorded two errors and zero tracks, yet returned success, marked both files processed, set 100% progress, and advanced the last-sync timestamp. The completed state offers a fresh sync, and the run is no longer resumable. [Per-file failure handling](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1282) · [Run finalization](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1401) · [Progress sheet](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/presentation/widgets/sync_progress_sheet.dart#L235)

### Discovery and recovery

6. **The folder picker omits later pages.** With 100 folders on page one and another on page two, the folder repository returned 100 entries after one HTTP request. The field mask omits `nextPageToken` and there is no paging loop. Drive can return fewer than 100 entries on a page, so this also affects shorter first pages that carry a token. Recursive sync successfully followed a token on an empty first page in the control case. [Folder list](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L54) · [Google Drive files.list reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list)

7. **Retry can retain a track missing from the new listing.** Start with A and B indexed. In a fresh run, return B on page one and HTTP 503 on page two. The failure preserved both local tracks. Resume with a successful root listing containing only A. The run completed with two discovered tracks and kept B because it merged the new listing with persisted rows from the failed scan. [Partial discovery restoration](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L855) · [Discovery merge](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L933)

8. **Recovery after a process interruption during discovery starts at the root.** Snapshot SQLite after page one commits, while page two is held in flight. The snapshot contained the first discovered row with both folder checkpoint fields null. Startup recovery on a new repository listed the root again. Traversal state is persisted on a graceful stop, so it is unavailable for process interruption at that point. [Startup recovery](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L210) · [Folder state callback](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L969)

9. **Resume drops Force Full Re-sync mode.** Start a force run over two already indexed, unchanged files. Stop during the first download and resume. Only the first file was downloaded, and the run finished with one update. The resume entry point has no persisted force flag. Resume also rewrote the first file’s `updated` status to `unchanged` even though the run still counted the update. [Resume arguments](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L306) · [Classification and unchanged writes](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1056) · [Run schema](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/core/database/tables.dart#L193)

10. **Stop can stall on a request or be ignored during reconciliation.** Holding an audio response kept the run in `stopping` and a replacement folder had to wait before listing. A separate stop request at the start of `updatingDatabase` still allowed a local removal and completed the run. Cancellation is checked between tracks and before reconciliation. The in-flight media request and reconciliation have no cancellation checks of their own. [Stop request](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L245) · [Folder switch](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L644) · [Final cancellation check](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1337)

### Metadata and storage

11. **Sidecar changes, removals, and transient errors can leave lyrics stale or missing.** Editing only an LRC left the original lyrics after an incremental sync with zero downloads. Removing the sidecar left those lyrics even after a force run. Separately, an LRC HTTP 503 left the audio checkpointed with zero reported errors, and an unchanged retry never requested the recovered sidecar. Lyrics processing is driven by audio classification and only saves when it obtains usable lyrics. [Track classification](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L592) · [Lyrics processing](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1985)

12. **Resume loses parent-folder artwork.** With `cover.jpg` in the selected folder and a track in a disc subfolder, stop after discovery and before metadata processing. Resume performed zero Drive list requests, downloaded only the audio, and stored no artwork. The scan builds the parent map in memory. Completed-discovery resume reads `drive_folders`, which the scan never populates. [Parent discovery](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L166) · [Parent map restoration](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L896) · [Artwork resolver](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/metadata/domain/services/folder_artwork_resolver.dart#L14)

13. **Force sync can keep an outdated cover.** After caching a folder cover, change its media bytes and force a re-sync. Only audio downloaded, and the cached cover still held the original bytes. Artwork resolution returns the existing album-keyed file before checking the Drive candidate. [Artwork cache lookup](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1795)

14. **A slash in a Drive filename can prevent import.** A listing with `Artist / Song.mp3` triggered a staging error and indexed zero tracks. The raw remote name becomes part of a local path, and the download tries to open a file under a directory that does not exist. [Temporary filename](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1188) · [Path construction](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/core/filesystem/app_file_system.dart#L91) · [Download file open](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L264)

15. **Remote deletion leaves audio on disk outside cache eviction.** After removing a cached, pinned track from the next Drive listing, sync deleted its track and cache rows but left the media file on disk. The cache still counted its bytes. Both clear-cache with pinned content included and LRU eviction targeting zero bytes left the file in place because they enumerate cache rows. [Deletion reconciliation](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1379) · [LRU eviction](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/cache/data/repositories/cache_repository_impl.dart#L284) · [Cache clearing and size](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/cache/data/repositories/cache_repository_impl.dart#L346)

### Progress reporting

16. **Scanning double-counts discovered audio.** A two-track response emitted scanning counts of 0, 0, 2, and 4, then reset to 2 at classification. The scanner reports a cumulative count after the library callback has already appended the same files. [Drive callbacks](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L202) · [Library callbacks](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L933)

17. **A successful retry can still display its old failure.** Fail a scan with HTTP 503, then resume with a successful listing. The original error message remained in both live complete progress and SQLite. Passing null to `copyWith` preserves the old value, and the run upsert and completion write omit the persisted error field. The sheet renders any non-null error message irrespective of phase. [Progress copyWith](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/domain/entities/sync_progress.dart#L77) · [Run finalization](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1401) · [Progress sheet banner](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/presentation/widgets/sync_progress_sheet.dart#L155)

18. **A paused progress subscriber can miss an entire run.** Read the first snapshot through a `StreamIterator`, leave it paused, and complete a fresh sync. On requesting the next element, no progress arrived within the probe’s wait, although SQLite recorded the new completed run. The generator yields the snapshot before it subscribes to the broadcast controller. [Progress stream](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L138)

## Additional edge cases from code review

- **Account transitions and startup recovery.** Sign-out removes cached user records. Sync roots, run state, and discovery rows use a single `source_gdrive` identity with `accountEmail = 'primary'`. Startup requests recovery even when no user was restored. A second Google account can inherit the previous account’s sync context. The end-to-end sign-out, switch-account, and token-revocation flows need a live Android check. [Sign-out](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/authentication/data/repositories/google_auth_repository.dart#L137) · [Sync source write](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L804) · [Bootstrap recovery](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/app/bootstrap/bootstrap.dart#L119)
- **Partial reconciliation and relationship rows.** Track, cache, and lyric deletions run in separate operations. An interruption after the track delete can leave associated data, and the next reconciliation enumerates existing tracks. The path also leaves favorite, playlist, playback queue, and history rows referencing removed tracks. The user-visible effects of those remaining references depend on each consuming query. [Reconciliation](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1361) · [Relationship tables](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/core/database/tables.dart#L132)
- **Large collections and slow sidecars.** Discovery walks accumulated lists to deduplicate and count on each new file, creating quadratic work across a large flat library. The unchanged-file update builds one SQL parameter list for all unchanged IDs. The failure threshold depends on the SQLite build. Sidecar download also runs inside the per-track transaction and can hold it open while waiting on Drive. These paths were reviewed without measuring library size or timing limits on Android. [Discovery callbacks](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L933) · [Batch update](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1086) · [Metadata transaction](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/library/data/repositories/music_library_repository_impl.dart#L1226)
- **Shared drives and shortcuts.** The picker starts at My Drive and neither listing supplies shared-drive options. The scan traverses actual folder MIME types and does not resolve shortcut targets. Shared-drive music and folder shortcuts remain live API coverage gaps. [Folder picker initialization](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/presentation/pages/drive_folder_picker_page.dart#L39) · [Drive listing and classification](https://github.com/blackpirateapps/musii/blob/75325cc93e8493f8ccef6498a39dca5da63d3fc7/lib/features/google_drive/data/repositories/google_drive_repository_impl.dart#L150) · [Google Drive files.list reference](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list)
